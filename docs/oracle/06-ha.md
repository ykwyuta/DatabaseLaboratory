## 構成と障害ドメイン

Data Guardはredoをstandbyへ送って回復する構成、RACは複数インスタンスが共有DBを扱う構成です。用途と障害ドメインが異なり、Freeの単体イメージで利用できると仮定しません。

<a id="section-2"></a>

## 同期方式と読み取り整合性

redo転送のSYNC/ASYNC、protection mode、standby適用遅延を区別します。受信済みredoと適用済みデータの差を読み取り要件へ反映します。

<a id="section-3"></a>

## 昇格・接続先切り替え・再参加

switchoverと障害時failoverを分け、旧primary隔離、サービス切替、アプリ再接続、standby再作成/復帰を計画します。broker/observer等は対応条件を確認します。

<a id="section-4"></a>

## 遅延監視とスプリットブレイン対策

V$DATAGUARD_STATS、V$DATABASE、archive destinationの状態とtransport/apply lagを監視します。複数writerを許さない役割管理と外部のfencingを設計します。

<a id="section-5"></a>

## RPO・RTOと障害試験

ログ欠落・転送停止・apply遅延・primary喪失を試験します。実施には対応するエディションと別ノード構成が必要で、DatabaseLaboratoryのFree単体検証結果とは分けて記録します。

<a id="examples"></a>

## 確認用の例と検証手順

```sql
SELECT database_role,open_mode,protection_mode FROM v$database;
```
現在のFree構成は単体です。Data Guard/RACの役割試験は対応環境を別途用意します。
