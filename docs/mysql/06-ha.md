## 構成と障害ドメイン

非同期source/replica、準同期、Group Replication/InnoDB Clusterを区別します。レプリカ1台と自動フェイルオーバークラスタは同義ではありません。Routerや管理基盤も構成に含めます。

<a id="section-2"></a>

## 同期方式と読み取り整合性

通常の非同期レプリカは遅延し、読み取り直後の整合性を保証しません。準同期の受領確認とSQL適用完了も区別し、Group Replicationではquorumと整合性設定を評価します。

<a id="section-3"></a>

## 昇格・接続先切り替え・再参加

昇格候補のGTID適用状況を確認し、旧sourceへの書き込みを停止してから接続先を切り替えます。復帰ノードのerrant transactionを検査し、必要なら再作成します。

<a id="section-4"></a>

## 遅延監視とスプリットブレイン対策

SHOW REPLICA STATUSとperformance_schema.replication_*を監視します。Seconds_Behind_Source単独では判断せず、IO/SQLスレッド停止、適用エラー、GTID差、relay log容量を見ます。

<a id="section-5"></a>

## RPO・RTOと障害試験

接続再試行・未確定トランザクションの再実行・二重書き込み防止を含めてRTOを測ります。Ravaの単体構成ではクラスタ障害時のRPOを測定できません。

<a id="examples"></a>

## 確認用の例と検証手順

```sql
SHOW REPLICA STATUS;
SELECT * FROM performance_schema.replication_group_members;
```
未構成では空です。GTID有効化やクラスタ構築は既存データの保全手順を別に設計して行います。
