## 構成と障害ドメイン

単体containerの再起動、standbyによるHA、DC間のDRを分けます。Operator管理の機能は対応Operator/agentの版と構成が必要で、Rava単体へ自動付属しません。

<a id="section-2"></a>

## 同期方式と読み取り整合性

同期/非同期の転送条件とstandby適用位置を定義します。DC間の非同期複製では遅延分の損失を評価し、最新読み取りの要求を接続先へ反映します。

<a id="section-3"></a>

## 昇格・接続先切り替え・再参加

昇格判定、旧primary隔離、service/endpoint切替、アプリ再接続、旧ノード再同期を設計します。単なるDocker restartをDBのHAフェイルオーバーとは呼びません。

<a id="section-4"></a>

## 遅延監視とスプリットブレイン対策

WAL送受信/適用LSN、slotの保持量、standby状態と管理プレーンの状態を監視します。quorum/fencingや共有ストレージの障害範囲も明示します。

<a id="section-5"></a>

## RPO・RTOと障害試験

primary/standby停止、DC分断、ディスク/WAL枯渇でRPO/RTOを測ります。マネージドAlloyDBのSLAをOmni単体の可用性へ転用しません。

<a id="examples"></a>

## 確認用の例と検証手順

```sql
SELECT pg_is_in_recovery();
SELECT application_name,state,sync_state,replay_lsn FROM pg_stat_replication;
```
Ravaはprimary単体なのでレプリカ行は空です。
