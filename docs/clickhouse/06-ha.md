## 構成と障害ドメイン

ReplicatedMergeTreeとKeeperによる複製、Distributedによるshardへのroutingを分けます。Replicated engineを使わないMergeTreeは自動で複製されません。

<a id="section-2"></a>

## 同期方式と読み取り整合性

replica間の非同期適用とINSERT quorum等の設定を確認します。すべての読取りが最新という保証はなく、lagしたreplicaの選択と読み取り要件を設計します。

<a id="section-3"></a>

## 昇格・接続先切り替え・再参加

一般的な単一primary昇格モデルとは異なり、利用replicaとrouting、Keeper quorumを管理します。故障replicaの再同期と削除、旧データの誤再参加を防止します。

<a id="section-4"></a>

## 遅延監視とスプリットブレイン対策

system.replicas/replication_queueの遅延、queue長、is_readonly/is_session_expired、Keeper状態を監視します。shard内replicaとshard間のデータ配置を混同しません。

<a id="section-5"></a>

## RPO・RTOと障害試験

replica停止・Keeper quorum喪失・network分断でINSERT/SELECTがどう失敗するか測ります。DatabaseLaboratory単体にはKeeperも複製engineもなく別環境が必要です。

<a id="examples"></a>

## 確認用の例と検証手順

```sql
SELECT database,table,is_readonly,absolute_delay,queue_size FROM system.replicas;
```
DatabaseLaboratory単体では空です。複製構成を追加した際はKeeperとreplica queueも収集します。
