## 構成と障害ドメイン

標準の非同期/準同期レプリケーションとGaleraのvirtually synchronousな構成を分けます。Galeraはwrite-setの認証とquorumに基づき、単純な共有ディスク構成ではありません。

<a id="section-2"></a>

## 同期方式と読み取り整合性

非同期の遅延読み取りと、Galeraの適用待ち・flow controlを区別します。Galeraでも読み取り整合性や競合失敗時の再試行をアプリ側で設計します。

<a id="section-3"></a>

## 昇格・接続先切り替え・再参加

標準レプリケーションの昇格とGaleraクラスタ再起動では判断手順が異なります。MaxScale等のルーティング・監視、旧writerの隔離、再参加時のSST/ISTを計画します。

<a id="section-4"></a>

## 遅延監視とスプリットブレイン対策

SHOW SLAVE STATUSとGTID位置、Galeraならwsrep_cluster_status/wsrep_ready/flow controlを確認します。非Primary componentを強制的に複数起動する運用を避けます。

<a id="section-5"></a>

## RPO・RTOと障害試験

ノード停止・過半数喪失・遅延・ネットワーク分断を試し、コミット済みデータと接続再開を確認します。DatabaseLaboratoryにはGaleraや監視基盤を含めていません。

<a id="examples"></a>

## 確認用の例と検証手順

```sql
SHOW SLAVE STATUS;
SHOW GLOBAL STATUS LIKE 'wsrep_%';
```
DatabaseLaboratory単体ではレプリケーション結果は空、wsrepは無効です。
