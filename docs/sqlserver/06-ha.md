## 構成と障害ドメイン

Always On AGはDB単位のレプリカ、FCIはインスタンス単位の切り替えです。LinuxのPacemakerやcluster type、共有ストレージ、listenerを構成に合わせて選びます。

<a id="section-2"></a>

## 同期方式と読み取り整合性

同期コミットと非同期コミットを区別します。同期でもsecondaryのredo完了と同じとは限らず、readable secondaryでの読取整合性・遅延を確認します。

<a id="section-3"></a>

## 昇格・接続先切り替え・再参加

同期状態とquorumを確認してplanned failover、強制昇格、旧primaryの隔離・再同期を手順化します。listener、DNS、接続文字列、connection poolの再接続を含めます。

<a id="section-4"></a>

## 遅延監視とスプリットブレイン対策

dm_hadr_database_replica_statesのlog_send_queue_size/redo_queue_sizeと同期状態を監視します。quorumとfencingがない単なる2台構成で自動昇格を実装しません。

<a id="section-5"></a>

## RPO・RTOと障害試験

primary停止・ネットワーク分断・ログ遅延でデータ損失と復旧時間を測ります。Developerの単体ComposeだけではAGの可用性を実証できません。

<a id="examples"></a>

## 確認用の例と検証手順

```sql
SELECT SERVERPROPERTY('IsHadrEnabled');
SELECT synchronization_state_desc,log_send_queue_size,redo_queue_size FROM sys.dm_hadr_database_replica_states;
```
DatabaseLaboratoryではHADR未設定です。
