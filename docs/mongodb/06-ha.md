## 構成と障害ドメイン

replica setはprimaryと複数secondary、shardingはデータ分割です。shardごとのreplica setとconfig server、mongosの役割を分けて設計します。

<a id="section-2"></a>

## 同期方式と読み取り整合性

非同期複製を基本にwriteConcern majorityとreadConcern/readPreferenceを指定します。secondary読み取りは遅延し得ます。majority ackの耐久性はjournal設定等も含め確認します。

<a id="section-3"></a>

## 昇格・接続先切り替え・再参加

過半数による選出、driverのtopology検出、再接続、retryable write/transactionを試験します。失われたprimaryへの古い接続や、rollbackされる書込みの扱いを定めます。

<a id="section-4"></a>

## 遅延監視とスプリットブレイン対策

rs.status()、replication lag、oplog window、election履歴を確認します。投票ノード配置とquorumを設計し、同一ホスト内replica setを災害対策とは扱いません。

<a id="section-5"></a>

## RPO・RTOと障害試験

primary停止、少数派の分断、oplog保持期間超過を試します。現Composeはstandaloneで、electionもmajority replicationも検証範囲外です。

